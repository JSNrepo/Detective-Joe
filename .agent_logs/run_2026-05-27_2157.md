## What you discovered
During the code review, I identified unhandled errors resulting in command injection vulnerabilities within the plugin architecture. The various `*_plugin.py` files interpolated user inputs (such as `target`, `ports`, `args`, etc.) directly into shell commands without proper escaping or sanitization. This lack of sanitization left the application vulnerable to command injection, where a malicious user could execute arbitrary shell commands by crafting inputs that break out of the intended command structure.

## What you fixed/added
To resolve this issue, I updated the following files to import the `shlex` module and use `shlex.quote()` to properly escape all user-controlled inputs before they are interpolated into shell commands:
- `plugins/demo_plugin.py`
- `plugins/dnsrecon_plugin.py`
- `plugins/nmap_plugin.py`
- `plugins/sslscan_plugin.py`
- `plugins/sublist3r_plugin.py`
- `plugins/theharvester_plugin.py`
- `plugins/whatweb_plugin.py`
- `plugins/whois_plugin.py`

This ensures that the user inputs are safely passed as arguments to the command-line tools without risking command injection.
