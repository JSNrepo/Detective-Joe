What you discovered.
The reconnaissance plugins constructed shell commands for execution (via `asyncio.create_subprocess_shell`) by directly interpolating potentially user-provided input variables such as `target`, `ports`, `scan_type`, and other scan parameters. Because these strings were executed in a shell environment, this permitted potential command injection attacks using shell metacharacters.

What you fixed/added.
Updated eight plugins (`demo_plugin.py`, `dnsrecon_plugin.py`, `nmap_plugin.py`, `sslscan_plugin.py`, `sublist3r_plugin.py`, `theharvester_plugin.py`, `whatweb_plugin.py`, and `whois_plugin.py`) to import `shlex` and wrap all interpolated variables inside `shlex.quote()`. This ensures arguments are securely escaped before the command is evaluated by the shell.

Next Recommended Target
Review `export_utils.py` and `report_webview.py` for potential XSS or path traversal vulnerabilities, especially related to the rendering or parsing of dynamically generated reports and arbitrary file accesses.
