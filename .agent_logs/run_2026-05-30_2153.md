What you discovered.
I discovered a critical Command Injection vulnerability in the plugin architecture. In `plugins/base.py`, the `asyncio.create_subprocess_shell` function was used to execute shell commands built by individual plugins. However, the `build_command` functions in these plugins were constructing shell commands by directly interpolating user input (such as `target`, `ports`, `scan_type`, etc.) using string formatting without proper sanitization. This allowed attackers to inject arbitrary shell commands by appending shell metacharacters like `;`, `&&`, or `|` to the user input.

What you fixed/added.
I fixed the Command Injection vulnerability by introducing `shlex.quote()` to sanitize all user inputs before they are interpolated into shell commands. This ensures that user inputs are treated as literal strings and not evaluated as shell commands. I updated the following plugins:
- `plugins/nmap_plugin.py` (target, ports, timing, script)
- `plugins/demo_plugin.py` (target)
- `plugins/theharvester_plugin.py` (target, sources, limit, format)
- `plugins/sublist3r_plugin.py` (target, threads)
- `plugins/whatweb_plugin.py` (target, aggression)
- `plugins/whois_plugin.py` (target)
- `plugins/dnsrecon_plugin.py` (target, type)
- `plugins/sslscan_plugin.py` (target, port)

Next Recommended Target
The next recommended target should be reviewing other uses of subprocess/shell executions if any exist, or starting to address the numerous style (PEP 8) issues reported by `flake8`, particularly regarding line lengths, blank lines, and unused imports to improve codebase maintainability.
