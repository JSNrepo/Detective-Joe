What you discovered.

Inefficient algorithm in `async_worker.py` where a list comprehension was used inside a polling loop to check for pending tasks, causing unnecessary O(N) memory allocations per cycle.

What you fixed/added.

Replaced the list comprehension with an `any()` generator expression in `async_worker.py` (lines 201-207), which evaluates lazily and avoids creating a new list each cycle. Added an inline comment explaining the optimization.

Next Recommended Target

Other modules should be reviewed for similar inefficient algorithms, such as list comprehensions that can be replaced with generators.
