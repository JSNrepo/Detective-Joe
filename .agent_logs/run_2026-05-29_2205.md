What you discovered.
Command injection vulnerabilities were identified within the plugin architecture, specifically in the `build_command` functions of multiple reconnaissance plugins (`demo_plugin.py`, `dnsrecon_plugin.py`, `nmap_plugin.py`, `sslscan_plugin.py`, `sublist3r_plugin.py`, `theharvester_plugin.py`, `whatweb_plugin.py`, and `whois_plugin.py`). The vulnerability was caused by string interpolation of user-supplied inputs directly into shell commands without appropriate quoting or sanitization, potentially allowing arbitrary command execution.

What you fixed/added.
Imported the `shlex` module into the affected plugins. Modified the `build_command` methods to use `shlex.quote()` on user-provided inputs such as target domains, scan types, port configurations, threads, output formats, and source options before they are interpolated into shell strings.

Next Recommended Target
Further harden the plugin architecture by enforcing an execution model that inherently avoids shell invocation (e.g., executing commands via `asyncio.create_subprocess_exec` with a list of arguments instead of `asyncio.create_subprocess_shell` with strings) to completely eliminate risks of shell injection.
