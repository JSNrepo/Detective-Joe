# Daily Improvement Log

## What was discovered

I discovered a command injection vulnerability in the plugin architecture. The base plugin class `plugins/base.py` executes commands using `asyncio.create_subprocess_shell`. The commands are built in individual plugins (like `plugins/dnsrecon_plugin.py`, `plugins/nmap_plugin.py`, etc.) using string formatting without proper sanitization (e.g., `cmd = f"dnsrecon -d {target} -t {scan_type} -j -"`). This could allow malicious user input (like a target name containing shell metacharacters) to execute arbitrary commands on the system.

## What was fixed/added

I updated the `build_command` functions in the following plugins to use `shlex.quote()` to properly sanitize variables interpolated into shell commands:
- `plugins/dnsrecon_plugin.py`
- `plugins/nmap_plugin.py`
- `plugins/sslscan_plugin.py`
- `plugins/sublist3r_plugin.py`
- `plugins/theharvester_plugin.py`
- `plugins/whatweb_plugin.py`
- `plugins/whois_plugin.py`

This ensures that any inputs (target, ports, threads, etc.) are safely escaped, preventing command injection vulnerabilities. Note: `plugins/webcheck_plugin.py` was already properly implemented using `shlex.quote()` inside its own python script building, and `plugins/demo_plugin.py` didn't have user variables directly in a way that requires fixing right now in this context.

## Next Recommended Target

The next recommended target should be checking and optimizing the way external tools are called in `asyncio.create_subprocess_shell` regarding timeouts. Ensure that any zombie processes are thoroughly cleaned up when a timeout occurs, especially given that some tools might spawn child processes of their own. Alternatively, adding a missing typing hint in core engine files.
