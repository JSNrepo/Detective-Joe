What I discovered:
A command injection vulnerability exists across multiple reconnaissance plugins (`nmap`, `theharvester`, `sublist3r`, `whatweb`, `whois`, `dnsrecon`, `sslscan`, `demo`). These plugins dynamically build shell commands using raw strings from user input or configuration. The unescaped injection of these strings directly into shell commands via `asyncio.create_subprocess_shell` allowed arbitrary command execution by escaping parameter boundaries.

What I fixed/added:
- I applied `shlex.quote()` to all variables containing string data before they were incorporated into the shell execution strings in the `build_command` functions of all vulnerable plugins (`nmap`, `theharvester`, `sublist3r`, `whatweb`, `whois`, `dnsrecon`, `sslscan`, `demo`). This ensures special characters are neutralized and properly treated as single safe arguments.
- Added a security learning entry in `.jules/sentinel.md` capturing the vulnerability details and proper prevention strategies.

Next Recommended Target:
Review the `asyncio.create_subprocess_shell` calls across the core framework files (e.g. `async_worker.py` or potentially hidden utility scripts) to see if similar vulnerabilities or potential environment manipulations exist outside of the plugin modules.
