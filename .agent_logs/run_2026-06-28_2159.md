What I discovered:
The `wait_for_tasks` method in `async_worker.py` used a full list comprehension inside a while loop to check for pending tasks, resulting in unnecessary O(N) memory allocation during every polling cycle.

What I fixed/added:
Replaced the list comprehension with an `any()` generator expression. This short-circuits evaluation and avoids creating intermediate list objects, improving memory efficiency.

'Next Recommended Target':
Review other polling mechanisms in `async_worker.py` for similar list comprehension memory inefficiencies.
