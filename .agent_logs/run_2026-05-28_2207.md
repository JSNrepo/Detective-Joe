What you discovered.
The plugin system creates shell commands dynamically using user inputs, and then runs them via `asyncio.create_subprocess_shell`. This exposes a command injection vulnerability where a malicious input (such as `example.com; rm -rf /`) could allow arbitrary command execution on the host machine.

What you fixed/added.
I edited `plugins/nmap_plugin.py`, `plugins/demo_plugin.py`, `plugins/theharvester_plugin.py`, `plugins/sublist3r_plugin.py`, `plugins/whatweb_plugin.py`, `plugins/whois_plugin.py`, `plugins/dnsrecon_plugin.py`, and `plugins/sslscan_plugin.py`. In these files, I used `shlex.quote` to properly sanitize user inputs, including the `target` parameter and other dynamic keyword arguments like `ports`, `sources`, and `limit`, before they are interpolated into the shell command strings. This ensures that command injection is prevented without altering the functionality.

Next Recommended Target
Review `report_webview.py` and `export_utils.py` for potential path traversal, XSS, or arbitrary file read vulnerabilities as they handle generating user-visible reports and files based on scan inputs and results.
