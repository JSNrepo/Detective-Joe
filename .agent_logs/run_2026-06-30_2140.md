What I discovered:
The `AsyncWorkerPool` in `async_worker.py` uses inefficient list comprehensions for counting active tasks and checking pending tasks. `len([t for t in self.tasks.values() if t.status == TaskStatus.RUNNING])` creates a full list in memory just to count elements. In `wait_for_tasks`, a list comprehension is used inside a polling loop to check if any tasks are still pending, causing O(N) memory allocations per polling cycle.

What I fixed/added:
Replaced `len([...])` with `sum(1 for ...)` using a generator expression to prevent unnecessary O(N) memory allocations. Replaced the list comprehension in the polling loop with a generator expression using `any()` to stop iteration early and prevent O(N) memory allocations per polling cycle. Added comments explaining the optimizations.
