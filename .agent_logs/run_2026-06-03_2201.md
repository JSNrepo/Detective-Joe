What you discovered.
Discovered a command injection vulnerability in the plugin architecture. Several plugins (`demo_plugin.py`, `dnsrecon_plugin.py`, `nmap_plugin.py`, `sslscan_plugin.py`, `sublist3r_plugin.py`, `theharvester_plugin.py`, `whatweb_plugin.py`, `whois_plugin.py`) were directly interpolating user inputs (like `target`, `ports`, `sources`) into shell command strings, which are executed using `asyncio.create_subprocess_shell`. This could allow an attacker to execute arbitrary commands by injecting shell metacharacters.

What you fixed/added.
Sanitized all dynamic user inputs interpolated into shell command strings by wrapping them with `shlex.quote()`. This ensures that user inputs are safely escaped and prevents any command injection attempts. The updates were made consistently across all affected plugins without breaking the existing testing pipeline.

Next Recommended Target
Add missing test coverage for the plugin error handling scenarios, ensuring that exceptions within specific tools are caught and logged appropriately without causing the asynchronous task queue to halt unexpectedly.
