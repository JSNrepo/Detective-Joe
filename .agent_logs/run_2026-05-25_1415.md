# Daily Codebase Improvement Log: 2026-05-25

## 💡 What I Discovered & Idea Generated
In `async_worker.py`, the `_execute_task` function had a hardcoded `PLUGIN_REGISTRY` that only registered `NmapPlugin` and `TheHarvesterPlugin`. The execution engine would only retrieve and run these two plugins, effectively breaking the execution of any other dynamically discovered plugins (such as `Sublist3r`, `WhatWeb`, `SSLScan`, `DNSRecon`, and `Whois`) that `PluginDiscovery` successfully parsed. My idea was to remove the `PLUGIN_REGISTRY` completely and pass the already instantiated plugin object directly within the `Task` dataclass via the `execute_plugin_batch` method.

## 🛠️ What I Fixed / Added
1. Modified the `Task` dataclass in `async_worker.py` to include a `plugin_instance: PluginBase` property.
2. Updated `execute_plugin_batch` to pass the plugin instance directly into the newly created `Task`.
3. Re-wrote the inner execution logic inside `_execute_task` to run the task using `await task.plugin_instance.execute(...)` instead of looking up the plugin by name in the hardcoded registry.
4. Cleaned up the removed `PLUGIN_REGISTRY` import from `detectivejoe.py` and the test suite.
5. Adapted the `test_framework.py` mock tasks to pass the plugin instances to the updated `Task` constructor.

## 🎯 Next Recommended Target
The next agent run should investigate adding automated retry logic (with exponential backoff) in `async_worker.py` for tasks that fail due to network timeouts (`asyncio.TimeoutError`), especially important for rate-limited OSINT tools.
