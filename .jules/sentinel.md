## 2026-05-29 - Command Injection in Plugin Subprocess Execution
**Vulnerability:** User-provided inputs (e.g., domains, ports, IP addresses, configuration strings) were interpolated directly into shell command strings without sanitization. These strings were then executed using `asyncio.create_subprocess_shell`. This presented a widespread command injection vulnerability across the reconnaissance plugins.
**Learning:** Shell strings constructed using formatting blocks like `f"cmd {target}"` are fundamentally unsafe when running untrusted inputs because any payload containing shell metacharacters (e.g., `;`, `&`, `|`, `$`) will be evaluated by the underlying shell rather than treated as a literal argument. Furthermore, applying `shlex.quote()` *inside* manually provided single quotes (e.g. `f"echo '{shlex.quote(target)}'"`) provides a false sense of security because `shlex.quote()` adds its own single quotes, which prematurely terminates the manually wrapped string and reopens the injection vector.
**Prevention:** Always use `shlex.quote()` on any dynamic variable placed within a shell command string, and guarantee that the `shlex.quote()` output is *not* enclosed in additional quotes. Alternatively, avoid `asyncio.create_subprocess_shell` entirely and execute binaries using `asyncio.create_subprocess_exec` passing the command and arguments as a list.
